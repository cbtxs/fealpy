# FEALPy | Task Brief | 调研成熟项目自动化测试系统

- **版本**：v0.1
- **状态**：草案
- **入库位置**：`kb/developments/new_mesh_module/mesh_02_test_system/survey_mature_projects_test_system/survey_mature_projects_test_system_task_brief.md`
- **启用条件**：当需要为“调研成熟项目自动化测试系统”子任务建立稳定本体表达时，本文件必须启用
- **适用范围**：FEALPy 新网格模块自动化测试系统建设任务；`survey_mature_projects_test_system` 调研子任务

本文档用于定义当前 Task 的稳定本体表达，回答该 Task 是什么、为什么成立、总体要解决什么问题，以及对象级完成判据为何。

## 一、Task 定位

本 Task 是新网格模块自动化测试系统建设任务中的调研子任务。

当前阶段不直接建设测试系统，也不直接编写新网格模块的大规模测试用例，而是先调研若干成熟项目在自动化测试系统上的常见做法，形成后续测试用例设计、测试目录组织、测试数据管理、CI 组织与失败报告设计的依据。

本 Task 的核心对象是“成熟项目自动化测试系统实践的调研与可迁移原则提炼”，而不是某一个具体测试工具的学习笔记，也不是 FEALPy 新网格模块测试实现本身。

## 二、核心问题与主目标

当前新网格模块处于重构与迭代过程中，需要一套可持续扩展、可回归、可复核的自动化测试机制。若直接开始写测试，容易出现测试目录混乱、测试粒度不清、测试数据不可复现、CI 执行范围不稳定、失败信息难以定位等问题。

本 Task 需要先回答以下核心问题：

1. 成熟 Python 科学计算项目、网格相关项目或工程化较成熟的开源项目，通常如何组织自动化测试系统。
2. 这些项目如何划分单元测试、集成测试、回归测试以及慢测试等测试层级。
3. 这些项目如何组织测试夹具、测试数据、参数化样例、随机种子、临时文件与失败报告。
4. 这些项目如何在 CI 中选择测试范围、输出结果、提供最小复现信息。
5. 其中哪些做法可以被 FEALPy 新网格模块直接借鉴，哪些做法不适合当前任务照搬。

本 Task 的主目标是形成一份面向 FEALPy 新网格模块的成熟项目测试系统调研结论，并提炼出可直接进入后续设计阶段的原则性输入。

## 三、输入与输出预期

本 Task 的输入包括：

- 新网格模块自动化测试系统建设任务的总体说明。
- 当前任务阶段对“调研成熟项目”的要求。
- 约 3 个成熟项目的公开测试组织、CI 配置、贡献指南或开发文档。
- FEALPy 新网格模块后续测试系统建设的约束与目标。

本 Task 的输出包括：

- 成熟项目自动化测试系统调研记录。
- 不同项目在测试分层、夹具组织、参数化、测试数据、回归策略、CI 触发与报告输出方面的对比结论。
- 可迁移到 FEALPy 新网格模块的设计原则。
- 不适合当前任务直接照搬的实践及原因说明。
- 面向后续测试用例生成和自动化测试系统设计的输入建议。

## 四、对象级完成判据

本 Task 达到对象级完成，需要满足以下条件：

1. 已选取约 3 个成熟项目作为调研对象，并说明选择依据。
2. 已围绕测试分层、测试数据、fixture、参数化、回归策略、CI 组织、失败报告等维度完成对比。
3. 调研结论不是停留在“项目使用了什么工具”，而是明确说明“为什么适合借鉴、借鉴什么、哪些不适合 FEALPy 新网格模块照搬”。
4. 已提炼出可复用设计原则，能够作为后续新网格模块测试用例设计和测试系统设计的依据。
5. 调研输出没有越界到其它 FEALPy 模块的测试建设，也没有把当前阶段扩展成大规模测试实现。
6. 文档内容可以被后续阶段直接引用，用于支撑最小测试矩阵、测试目录规范、测试数据组织与 CI 运行策略设计。

## 五、待确认点

- 最终选取的 3 个成熟项目是否固定为科学计算与网格相关项目，还是允许加入一个通用 Python 工程化项目作为对照。
- 是否需要把调研输出拆分为调研记录、对比表和原则清单三个独立文档。
