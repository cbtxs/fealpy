# FEALPy | Task Requirement | 调研成熟项目自动化测试系统 需求

- **版本**：v0.1
- **状态**：草案
- **入库位置**：`kb/developments/new_mesh_module/mesh_02_test_system/survey_mature_projects_test_system/survey_mature_projects_test_system_task_requirement.md`
- **启用条件**：当需要界定“调研成熟项目自动化测试系统”子任务的真实需求与成功条件时，本文件必须启用
- **适用范围**：FEALPy 新网格模块自动化测试系统建设任务；`survey_mature_projects_test_system` 调研子任务

本文档用于界定当前 Task 所要满足的真实问题、真实需求、约束条件与成功条件。

## 一、背景与核心问题

新网格模块自动化测试系统建设的目标不是临时补充若干测试，而是形成一套可持续扩展、可回归、可复核的测试机制。由于当前阶段仍处于测试系统建设前期，如果直接进入实现，容易出现测试范围失控、测试分层不清、测试资产难维护、CI 运行策略不稳定等问题。

因此，当前 Task 需要先调研成熟项目在自动化测试系统方面的常见做法，并将调研结果转化为 FEALPy 新网格模块可复用的设计原则。

当前 Task 需要解决的核心问题是：

1. 后续新网格模块测试系统应参考哪些成熟实践。
2. 哪些测试组织方式适合 FEALPy 新网格模块当前阶段。
3. 哪些做法虽然在成熟项目中存在，但不适合当前任务直接照搬。
4. 调研结论如何转化为后续测试用例设计、测试系统设计和 CI 组织的输入。

## 二、已确认需求

1. 调研对象数量应控制在约 3 个成熟项目，避免调研范围过大导致结论不可收口。
2. 调研对象应优先选择与 Python 科学计算、数值计算、网格处理、有限元或工程化测试实践相关的成熟项目。
3. 调研内容必须覆盖测试分层，包括单元测试、集成测试、回归测试，以及必要时的慢测试或性能测试。
4. 调研内容必须覆盖测试夹具、测试数据、临时文件、随机种子等可重复性保障方式。
5. 调研内容必须覆盖参数化测试如何减少重复样板，同时保持失败定位清晰。
6. 调研内容必须覆盖 AI 辅助生成测试如何转化为可审查、可维护的测试资产。
7. 调研内容必须覆盖 CI 中的测试选择、触发方式、失败报告、覆盖率输出和最小复现信息。
8. 调研结论不能停留在工具罗列层面，必须说明对 FEALPy 新网格模块的可借鉴点、不适合照搬点及原因。
9. 调研结果应能为后续新网格模块测试目录规范、测试数据组织、测试矩阵设计和自动化执行策略提供输入。
10. 调研阶段应保持任务边界，不直接扩展为测试实现、CI 实现或 Bug 修复阶段。

## 三、约束条件

1. 当前 Task 只面向新网格模块自动化测试系统建设的调研阶段。
2. 当前 Task 不包含 FEALPy 其它模块的测试建设。
3. 当前 Task 不要求完成新网格模块的完整测试覆盖。
4. 当前 Task 不应为了追求覆盖率而扩张到无关代码路径。
5. 当前 Task 不应将调研文档写成单一工具教程。
6. 当前 Task 对成熟项目的结论应尽量可追溯，避免基于印象做无依据判断。
7. 当前 Task 输出应能被后续任务复用，而不是只形成一次性阅读记录。
8. 当前 Task 中涉及的测试目录命名建议应与后续 `tests` 目录约束保持一致。
9. 当前 Task 对 AI 辅助测试的描述应强调人工复核、语义断言和可维护性，不应默认 AI 生成结果可以直接入库。

## 四、成功条件

本 Task 成功完成时，应满足以下条件：

1. 至少形成一份可入库的成熟项目自动化测试系统调研结论。
2. 调研对象选择清晰，能够说明每个项目为什么值得参考。
3. 对每个调研对象，至少覆盖测试分层、测试组织、测试数据或 fixture、参数化、回归策略、CI 组织与失败反馈等核心维度。
4. 输出中包含面向 FEALPy 新网格模块的复用判断，而不是只描述成熟项目自身做法。
5. 输出中明确列出可直接借鉴的设计原则，并说明这些原则如何服务于新网格模块测试系统。
6. 输出中明确列出不适合当前任务照搬的实践，并说明不适合的原因。
7. 输出能够为后续“最小测试矩阵”“测试用例生成”“自动化测试系统设计”提供直接输入。
8. 输出没有越界到新网格模块完整测试覆盖、其它模块测试、CI 实现或 Bug 修复。
9. 后续参与者可以基于本 Task 输出回答：新网格模块测试系统应优先借鉴哪些成熟实践，以及为什么。

## 五、待确认需求

- 是否需要在本阶段产出初版“最小测试矩阵”，或仅在调研结论中提供矩阵设计依据。
- 是否需要把调研输出拆分为调研记录、对比表和原则清单三个独立文档。
