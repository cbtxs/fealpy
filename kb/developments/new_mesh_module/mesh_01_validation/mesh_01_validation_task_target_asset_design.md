# FEALPy | Development Task | 新网格模块稳定化验证 | 目标资产设计

- **任务编号**：new_mesh_01_validation
- **任务类型**：Development Task
- **设计目的**：明确本任务最终应沉淀哪些可复用资产，以及这些资产分别服务什么职责

## 一、目标资产分层

本任务建议沉淀为三类资产：

- 任务设计资产：用于定义任务、边界、需求、网络、验证和目标对象
- 任务执行资产：用于承载算例、实现、测试与验证过程
- 任务目标资产：用于承载最终形成的可复用结果

## 二、当前阶段的主要目标资产

### 1. 任务指南

- **建议位置**：`kb/explanation/new_mesh_01_validation_task_guide.md`
- **资产类型**：Knowledge / Governance Asset
- **职责**：向网格组成员说明任务目标、分工方式、阅读顺序、输出要求与验证纪律
- **状态**：本次任务的直接交付物

### 2. 架构审查材料

- **建议位置**：`kb/developments/new_mesh_01_validation/`
- **资产类型**：Knowledge / Governance Asset
- **职责**：记录新网格模块中不合理之处、风险点与改进建议
- **形式**：问题清单、审查笔记、对照分析

### 3. 算例资产

- **建议位置**：`example/` 或 `app/` 下的网格相关目录
- **资产类型**：Code / Knowledge Asset
- **职责**：证明新网格模块可以完整支撑一个研究主线算例
- **形式**：可运行脚本、输入数据、运行说明、结果文件

### 4. 新网格类型资产

- **建议位置**：`fealpy/mesh/` 或其子目录中的相应 schema / storage / view / topology 文件
- **资产类型**：Code Asset
- **职责**：在新架构下实现一种新的网格类型，并可被注册、构造与查询
- **形式**：新实体 schema、必要存储扩展、关系构造补充、视图支持

### 5. 验证资产

- **建议位置**：`test/`、`kb/developments/new_mesh_01_validation/`、必要时配套 `example/`
- **资产类型**：Validation Asset
- **职责**：证明算例与新网格类型的正确性、稳定性与可复现性
- **形式**：测试脚本、验证脚本、验证说明、结果记录

## 三、目标资产命名建议

建议后续执行阶段沿用统一前缀：

- `new_mesh_01_validation_...`
- 新增算例文件应能与任务编号直接关联
- 新增测试文件应能直接回溯到验证对象

## 四、目标资产验收关注点

- 资产名称与职责是否一一对应
- 资产是否能被后续成员直接复用
- 资产是否能支撑后续更大规模的网格迁移工作
- 资产是否足以作为新网格模块稳定化的基础证据
