# FEALPy | Development Task | 新网格模块稳定化验证 | 任务需求

- **任务编号**：new_mesh_01_validation
- **任务类型**：Development Task
- **需求主线**：围绕新网格模块，完成“审架构、做算例、做新网格类型与验证”三条主线工作

## 一、总体需求

本任务需要让网格组成员能够在新网格模块上独立完成以下结果：

1. 理解模块分层与设计意图。
2. 找出当前架构中的不合理之处，并给出明确依据。
3. 用新架构完成一个可运行、可复现、可验证的算例。
4. 用新架构实现一种新的网格类型，并给出正确性验证方案。

## 二、架构学习与审查需求

每位参与者至少需要给出以下内容中的一部分，合并后应覆盖完整审查视图：

- 模块分层理解：`schema / storage / view / topology` 的职责说明
- 当前实现中的问题清单：至少说明问题表现、代码位置、潜在后果与建议方向
- 与现有 `kb/design/mesh/mesh-data-structure.md` 的一致点与偏差点
- 与 `kb/implementation/mesh/construct-pipeline.md`、`kb/implementation/mesh/boundary-info-inferrence.md` 的一致点与偏差点

审查不要求一上来就给终局重构方案，但必须能把问题说清楚。

## 三、算例需求

算例必须满足：

- 主流程完全依赖新网格模块完成
- 能体现网格模块的真实价值，而不是只做一个最小空壳示例
- 可以结合参与者自身研究主线
- 允许为完成算例补充必要的网格相关算法或 mesher
- 需要给出可复现入口、运行说明与基本结果说明

算例建议优先覆盖以下能力之一：

- 拓扑构造与实体查询
- 边界信息推断
- 几何量计算，如 barycenter、measure、normal、tangent
- 关系推断与局部索引推断

## 四、新网格类型实现需求

新的网格类型实现至少应满足：

- 能在新架构中明确落到 schema、storage、view 其中的正确位置
- 能被注册表或构造链路识别
- 能生成稳定的实体数据与关系数据
- 能在验证方案下被证明是正确的

如果新网格类型本身需要算法支持，则允许按需补充相关拓扑或 mesher 代码，但应避免把补充算法写成无边界扩散。

## 五、验证与测试需求

验证必须覆盖两个层次：

- 正确性验证：实体数、关系数、边界判定、几何量或构造结果应符合预期
- 过程验证：构造链路、关系推断、边界推断和新类型注册应可重复运行

至少需要形成以下一种或多种验证材料：

- 测试脚本
- 断言型单测
- 小规模可复现实验脚本
- 验证说明文档
- 结果截图、VTU 或其他可检查产物

## 六、完成判据

当且仅当同时满足以下条件，任务需求才视为已被满足：

- 架构审查结果可追溯
- 至少一个算例在新架构下可运行
- 至少一种新网格类型在新架构下可验证
- 相关验证材料可复用
- 任务指南能指向后续协作入口
