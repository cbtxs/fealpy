# FEALPy | Development Task | 新网格模块稳定化验证 | Validation 设计

- **任务编号**：new_mesh_01_validation
- **任务类型**：Development Task
- **验证主位**：证明新网格模块在结构、几何、关系与可复现性上的正确性

## 一、验证目标

本任务的验证不只检查“代码能跑”，还要检查“新架构是否真的可用、可解释、可扩展”。

至少需要验证以下四类问题：

- 拓扑构造是否正确
- 关系推断是否正确
- 几何接口是否正确
- 新网格类型与算例是否可复现

## 二、验证对象

### 1. 架构验证

验证 `schema / storage / view / topology` 的职责划分是否合理，至少确认：

- `EntitySchema` 只承担规则与操作，不直接持有实例事实
- `MeshBlock` 只承担事实与关系存储
- `EntityView` 只承担用户访问与视图封装
- `TopologyBuilder`、`TopologyInferer`、边界推断逻辑承担算法职责

### 2. 算例验证

验证算例是否真正完全依赖新网格模块主流程。

建议检查：

- 是否从 `MeshBlock` 或 `Mesh` 进入
- 是否通过 `EntityView` 获得几何或拓扑量
- 是否存在绕过新架构的旧接口调用
- 是否能稳定复现结果

### 3. 新网格类型验证

针对新实现的网格类型，至少验证：

- 实体数量是否符合预期
- 关系表是否完整
- 边界实体是否符合几何直觉或解析参考
- 面积、体积、法向、切向等几何量是否合理
- 构造与查询是否可重复

### 4. 回归验证

验证新内容不会破坏已有的基础链路：

- `construct` 与 `construct_lower_dims`
- 边界信息推断
- 局部索引推断
- 既有 schema 的基本查询能力

## 三、验证方式建议

### 方式 A：断言型单测

适合验证实体数、关系数、边界数量、索引映射等离散结果。

### 方式 B：小规模解析对照

适合验证新网格类型的几何量、边界实体、构造关系是否符合已知参考。

### 方式 C：端到端算例回放

适合验证一个研究主线场景下，模块是否能从构造、查询、计算一路跑到结果输出。

### 方式 D：结果文件检查

如有必要，可输出 VTK 或其他可视化文件，用于人工复核网格结构。

## 四、建议的判定标准

- 结构正确：对象边界清楚，关系方向明确
- 几何正确：measure / barycenter / normal / tangent 结果可接受
- 拓扑正确：关系和边界不出现明显错误
- 可复现：同样输入得到稳定输出
- 可扩展：新网格类型接入后不需要大范围破坏性修改

## 五、建议的验证产物

- `test/` 下的断言型测试文件
- `example/` 下的可运行算例脚本
- 验证说明文档
- 结果记录或截图
- 如有必要，生成一份面向收口的验证摘要
